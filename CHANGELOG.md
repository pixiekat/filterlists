# Changelog

All notable changes to Pixie's Filterlists, newest first.

**Scope:** 2025-09-09 → 2026-10-01 (251 commits).

**A note on the automated commits:** 45 of those commits are `Automated filterlist update: …`,
generated by `build_filterlists.sh` when it pulls upstream sources and recompiles the metalists.
They carry no hand-authored intent, so they're summarised as a count at the end of each month
rather than listed one by one.

**Categories used below:**

- **Added** — new domains, new lists, new files.
- **Changed** — reorganisation, retuning, scope changes to existing lists.
- **Fixed** — syntax errors, broken rules, sites that stopped working because of over-blocking.
- **Removed** — domains or lists taken back out.
- **Tooling** — build scripts, automation, docs.

## Conventions that emerged in the lists themselves

Three habits developed over the year that are worth writing down, since they're not obvious
from reading a single rule:

**The sentinel-domain idiom.** Blocklist entries in `ublock/pixies_blacklist.txt` carry a
negated pseudo-domain that doesn't exist, e.g.:

```adguard
||foxnews.com^$document,all,domain=~its-a-fascist-domain.*
```

Because `~its-a-fascist-domain.*` can never match a real page, the exclusion never fires and
the rule applies everywhere — the tag is purely a **self-documenting category label** that
survives into the compiled output. Current vocabulary, by frequency:
`its-a-fascist-domain` (88), `scourge-of-society` (30), `its-a-racist-subreddit` (17),
`mv3-bootlicking-file` (10), `its-a-terf-apologia-site` (6), `its-a-fascist-subreddit` (5),
`its-a-terf-apologia-subreddit` (4), `mv3-bootlicking-site` and
`mv3-bootlicking-alleged-extension` (3 each), `its-tabloid-gutter-trash` (2), plus one-offs.
This convention is local to the hand-authored blacklist — it doesn't come from upstream.

**Version stamps.** Hand-edited lists carry a `! Version: DDMonthYYYYvN` header
(e.g. `! Version: 31August2026v1`), bumped by hand on each edit. It's a change marker for
subscribers, not a semantic version.

**Geo-spoofing via `$replace=`.** Age-assurance walls are worked around by rewriting the
JSON the site uses to locate you, rather than by blocking anything:

```adguard
||ip.bsky.app/config$replace=/(?<="countryCode":").+?(?=")/US/
||ip.bsky.app/config$replace=/(?<="isAgeRestrictedGeo":)true/false/
```

These need **Allow custom filters requiring trust** enabled in uBO options, which is noted
inline in the list.

## Conventions going forward

If you want to keep this file current without much effort:

- Skip the `Automated filterlist update:` commits entirely — they're machine output.
- Write hand-authored commit messages with the *why* in them where it isn't obvious
  (`adding youporn.com because uk sucks` is genuinely more useful a year later than
  `adding domains` would have been).
- Group by month rather than by version — this repo has no release cadence, and the
  version string in the compiled lists is a build timestamp, not a semantic version.
